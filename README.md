# Breaking Down Context Rot in LLMs

Long-context degradation is usually reported as a single curve: accuracy falls as the
window fills. This work takes that curve apart and asks which distinct mechanisms are
inside it, and which of them actually cost anything.

Four candidates are separated and tested one at a time.

- **Accumulation** is the null arm. Filling a window with unrelated turns does not by
  itself hurt accuracy. Reporting context rot as a length effect attributes the damage to
  the wrong thing.
- **Displacement** costs. As context grows, the evidence span loses attention mass to the
  rest of the window, and accuracy tracks the mass rather than the token count.
- **Competition** costs on some model families. A near-duplicate distractor competes with
  the evidence, and closing the competitor span recovers 56% of the penalty on OLMo-2-7B.
- **Precedent** costs. Once the model has seen a demonstrated answer format, it keeps
  answering in that shape instead of the instructed one, and that state is readable and
  installable.

Competition is architecture-indexed. The same panel on Qwen2.5-7B shows no penalty, and
its attention signature inverts. Positive claims about competition rest on OLMo, and the
divergence is discussed in the paper rather than averaged away.

The paper is `context_fatigue_paper/context_fatigue.pdf`.

## Finding the experiment behind a claim

Experiments are numbered E1 through E7, and the numbering runs through the driver flags,
the results directories, and the run notes. This table is the index.

| Mechanism | Paper | Code | Driver | Run note |
|---|---|---|---|---|
| Accumulation (null) | §4.1 | — | `run_random_context.py` | `QWEN_RANDOM_CONTEXT.md` |
| Displacement | §4.2 | E1, E2A | `run_distance_sweep.py`, `run_mass_clamp.py` | `E1_DISTANCE_SWEEP.md`, `E2A_MASS_CLAMP.md` |
| Competition | §4.3 | E3, E3c | `run_competition_sweep.py` | `E3_COMPETITION.md`, `E3C_COMPETITOR_CLOSE.md`, `E3C_HOT_CLOSE.md` |
| Precedent | §4.4, §4.5 | E5, E6 | `run_system_clamp.py`, `run_format_erosion.py` | `E5_SYSTEM_CLAMP.md`, `E6_CLOSE_WINDOWS.md` |
| The mode | §4.5 | E7 | `run_format_patch.py`, `run_format_probes.py` | `E7_FORMAT_PATCH.md`, `QWEN_E7_BISECTION.md` |
| Signatures | §4.6 | — | `run_olmo_attention.py` | `CONTEXT_ROT_ATTENTION.md` |
| Per-head structure | App. F | E4, E1d | `run_distance_sweep.py`, `run_evidence_clamp.py`, then `analyze_head_structure.py` | `E4_HEAD_STRUCTURE.md`, `E1D_HEAD_PATTERN.md` |
| Qwen replication | App. J | all | same drivers, `qwen_` prefixed outputs | `QWEN_*.md` |

A `QWEN_` prefix on a run note or results directory means the cross-family replication. A
`_preflight` suffix means a small validation run made before the real one. A `VOID` in a
directory name means the run was discarded, and the run note says why.

## Tracing a number back to its source

Every number in the paper is meant to be traceable. The chain has four links and runs in
both directions.

1. **The paper** makes a claim, for example the 0.42 delimiter-mass figure in §4.3.
2. **`context_fatigue_paper/numbers.md`** has a section per paper subsection. Find the
   claim in the table. The row gives the value, the artifact file, and the run note.
3. **The run note** in `results/context_fatigue/` opens with a verdict, then records the
   run date, model, seed, and the exact driver command. `E3C_HOT_CLOSE.md` for that claim
   names `run_competition_sweep.py --close-arms --measured-close 1.0 --store-rows`.
4. **The artifact** is `summary.json` for run-level configuration and aggregates, and
   `turns.csv` for the per-case rows the statistics were computed from.

Going the other way, if you have a results directory and want to know what it is, the run
note sharing its name prefix explains it, and `numbers.md` tells you whether the paper
uses it.

Read `AUDIT_2026-08-26.md` before trusting any single number. Six verification passes
recomputed every claim that could be recomputed from committed artifacts. It lists what
reproduced, five values that were corrected or withdrawn, and the gaps that remain open.

## The library

`src/probes/context_fatigue/` holds the machinery the drivers share.

| Module | What it does |
|---|---|
| `context_assembly.py` | builds the multi-turn contexts, filler and distractor arms |
| `attention_clamp.py` | the span-attention clamp. Scale 1 is a bit-identical no-op, scale 0 removes the span from attention, which the paper calls closing |
| `attention_capture.py` | selective capture of attention rows without holding the full tensor |
| `activation_patch.py` | the E7 counterfactual patching |
| `instruction_checks.py` | instruction and format grading, the prompt templates |
| `ddxplus_cases.py` | case construction from DDXPlus |
| `dilution_analysis.py`, `head_analysis.py`, `null_statistics.py` | analysis |
| `wildchat_data.py`, `wildchat_homogeneity.py` | the WildChat filler stream |
| `paper_figures.py` | figure generation, reads results/ and writes the figure PDFs |

## Artifacts

What is tracked here is `summary.json`, `turns.csv`, the run notes, and the vendored data
panels. That is the provenance chain and it belongs in git.

What is not tracked is the raw `.npz` state dumps. There were 546 of them at 422 MB against
3.9 MB for everything else, so they were stripped at the split and stay on the compute box.
Nothing in the test suite reads them. `docs/ARTIFACTS.md` has the inventory and explains
how to re-attach them.

Do not add a blanket `results/` or `data/` rule to `.gitignore`. The original shared repo
had one and 995 files were force-added past it, so the ignore file said the opposite of
what the repo did.

## Known gaps

`make test` gives 312 passes and 9 failures on a fresh clone. The 9 read artifact
directories that were never committed, mostly the OLMo E6 erosion program and the original
competition and head runs. The 2026-08-26 audit found this and `docs/ARTIFACTS.md` lists
exactly which directories are missing. Recovery is in progress and tracked in
`tasks/todo.md`. Those tests should pass once the artifacts land.
